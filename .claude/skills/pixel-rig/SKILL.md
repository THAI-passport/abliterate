# pixel-rig

A character is a set of **parts** (head, torso, arms, legs) drawn once per direction as small text
grids, plus a **pose library** that moves and swaps them, plus **layers** (face, hair, clothes)
that ride on the parts. The rig assembles every frame deterministically. Nothing is generated by a
model: `production.md` (Art) rules that out, and PixelLab was considered and declined
(`docs/PixelTech.md`).

Read `docs/pixel_art.md` (sections 3, 4, 7 and 9) for canvas, sizes, lighting and animation timing,
and `docs/character_design.md` for how each character looks (bodies, head kit, signatures).
Characters are lit from the top left, outlined, with a flat contact shadow; never restate the size
numbers here — the owning docs decide them.

## Files

The base rigs are `art/src/rig/body-a/` and `art/src/rig/body-b/`. Formats in full:
`references/formats.md`.

| File | Holds |
|---|---|
| `rig.json` | canvas, origin, directions, `mirror`, `fallback`, where each part sits per direction, draw order per direction, groups, outline, shadow |
| `parts/<part>.<dir>[.<variant>].txt` | one text grid per part, direction and variant (`sit`, `reach`, ...); optional `pivot: x,y` header |
| `../poses.json` | the pose library, shared by every body that uses the same part names |
| `../swaps.json` | colour swaps: skin sets map one palette ramp onto another; cloth sets map names |
| `layers/<name>/` | an outfit layer: drawn grids named like parts, and/or `layer.json` with paint rules |
| `../appearances/<name>.json` | one look: its layers (in order) and swaps |

## Commands

```bash
pt() { python3 tools/pixel-core/pixel_tech.py "$@"; }
pt rig-check art/src/rig/body-a/rig.json
pt rig-mirror-check art/src/rig/body-a/rig.json --layer hair-short
pt rig-build art/src/rig/body-a/rig.json --appearance art/src/rig/appearances/mr-pitt.json \
  --only-pose idle --direction down --out-dir build/art/rig/mr-pitt
pt rig-onion-skin art/src/rig/body-a/rig.json --appearance art/src/rig/appearances/mr-pitt.json \
  --pose walk --direction down --output art/previews/rig/mr-pitt-walk-onion.png
pt rig-test-sheet art/src/rig/body-a/rig.json --appearance art/src/rig/appearances/casual.json \
  --skin skin:light --skin skin:deep --background art/src/tiles/front-5-golden-parachute-carpet.txt \
  --output build/art/rig/test-sheet.png
pt rig-wardrobe art/src/rig/body-a/rig.json --appearance art/src/rig/appearances/suit.json \
  --column skin:light --column skin:medium --column skin:dark --column skin:deep --output build/art/rig/wardrobe.png
```

`rig-build` writes `sheet.png`, `atlas.json` (Phaser, frames named `appearance/pose/direction/i`),
`anims.json` (one animation per pose and direction, durations from the 60 fps holds),
`sheet-preview.png` (1× and 4×), and `-1x` / `-4x` GIFs per pose and direction. The legacy unsuffixed
GIF remains the 4× copy.

## How to work

1. **One direction first.** Draw and approve `down` (front) before `up` and `left`. `right`
   mirrors `left` (`"mirror": {"right": "left"}`) only while the design is symmetrical; an
   asymmetric outfit (a pocket square, a side parting) needs its own `right` drawings.
2. **Parts carry no outline.** The rig adds one outer outline around the whole figure, so gaps
   between arm and torso become clean ink lines. Draw a 1-px transparent gap where a limb should
   separate.
3. **Draw skin in the `skin-light` ramp** (darkest to lightest; use the ramp, not name guessing). Skin
   sets in `swaps.json` use `{"from_ramp": "skin-light", "to_ramp": "skin-deep"}`.
4. **Clothes that follow the body are paint rules.** A shirt is "torso rows 1–7 and arm rows 0–2,
   skin → cloth colours". It follows every pose, direction and variant for free. Give variants
   their own rule when the rows differ (see `layers/shirt/layer.json`). Earlier layers paint first.
5. **Clothes that change the silhouette are drawn layers.** Hair, hats, lapels, a trench coat,
   a janitor's apron: a grid named like the part it rides on (`torso.down.txt`), aligned to the
   same pivot. `"z": "top"` draws above every part; `"mode": "replace"` hides the part under it.
   Layers never fall back to another direction unless `layer.json` says `"fallback": true`.
6. **Poses are offsets, not drawings.** A frame moves parts or groups (`dx`, `dy`), picks a
   `variant`, or hides a part. Use `keys` plus `inbetween` to tween. Per-direction overrides go
   under `directions`. New poses go in the shared `poses.json`.
   Use appearance `frameLayers` when one frame adds or removes a drawn layer. Use
   `rig-onion-skin` to inspect the result.
7. **Character timing and posture live in appearance data.** Use `posture` for rig-defined
   profiles, `poseOverrides` for character-specific frames or holds, and `timeVariants` for named
   story states selected with `--variant`. Use `familyInherit` plus `--family-appearance` for a
   related look; do not duplicate creator logic.
8. **Held props follow hand anchors.** Put `anchor-hand: x,y` on each arm grid and
   `anchor-grip: x,y` on each direction of the prop. Add the prop through appearance `heldProps`
   or a pose frame's `props` list. A prop can draw at `z: bottom` or, by default, on top.
9. **Special silhouette rules are explicit.** Set appearance `shadow: false` only when the design
   calls for it. Mark a layer `"asymmetric": true`; `rig-check` then requires the bespoke mirrored
   direction. Native portrait layers belong in the 64×64 portrait kit (decision 37; drawn with
   real shading per the `pixel-face` skill's "Portraits") and are composed with
   `rig-portrait-kit`, never enlarged from the overworld sprite. `rig-portrait` gives a 4× bust
   starter for proportions only.
10. **Check readability, not just correctness.** Always run `rig-test-sheet` on the five front
   carpets and look at the **1×** row. A character passes only if it reads at 1× on the Golden
   Parachute carpet. A successful build is not approval; the owner approves.
11. **Check mirroring.** Run `rig-mirror-check` before accepting a mirrored direction. A reported
   detail needs deliberate review or a bespoke target-direction grid.

## The cast

Each cast member is an appearance: shared parts, their own layers and swaps. Keep their silhouettes
distinct (`pixel_art.md` section 7): Mr. Pitt's posture and suit, Mr. M's coat, Ms. Teller's visor,
each janitor's cart and apron, the dealers' vests in their front's colours (`docs/dialogue.md`
section 17). Every drawn layer exists in all four directions unless the owner has approved a
front-only exception (`character_design.md` section 1, rule 7).

## Quality bar

- Judge every result at **1× on the real carpets** (the `rig-test-sheet` 1× row) before judging the
  4× row. A character that only reads enlarged does not read.
- Open and look at every output — sheets, GIFs, onion skins — before showing it. A clean build is
  not a look.
- Draw at least two variants for any new part or layer and record in the commit why one won.
- All four directions, never front-only. An asymmetric detail (a pocket square, an earpiece) gets a
  drawn `right` view; `rig-check` and `rig-mirror-check` enforce this.
- **A walk must step.** A new walk pose needs contact and passing leg drawings, not offsets that
  only bob the body (`character_design.md` section 12).
- **Heads are skulls, not boxes.** A side view is deeper than the front is wide, the cranium sits
  behind a drawn ear, the back of the skull and the crown are round, and hair follows the skull.
  The rules live in the `pixel-face` skill ("Head anatomy") and are tested; any change to a head
  or to hair gets its side view rendered and looked at before commit.
- **The cast never clones.** Characters differ in head, hair or build, not only in colour — the
  corporate janitors are the one deliberate exception (`character_design.md` section 1, rule 10).
- Never generate geometry by rule where the format expects a drawn grid; every placed detail is
  re-rendered and looked at in context.

Nothing depicts or implies self-harm, in any pose, prop or expression (`docs/production.md`).

## Checks before commit

- `pt rig-check` passes; `python3 -m unittest discover -s tools/pixel-core/tests` passes.
- Open the test sheet and the wardrobe matrix and look at them at 1× and 4×.
- No emoji, brands or logos in any art; palette colours only.

## Handoff

- Commit at each phase boundary; a phase is a reviewable unit (one body, one outfit set, one fix).
- If work stops mid-phase, leave a short progress note (done / left) in the task doc or the commit
  message so the next agent does not have to reconstruct it.
- The rig is a deterministic builder and never skips regenerating an existing output: a changed
  part, pose, layer or appearance must change the built frames. Re-run `rig-build` (and the cast
  builders) and confirm the diff is exactly what you intended before committing.
- The owner approves character art in the running game; never mark art approved on their behalf.
